# The Curator — Development Guide

This file exists so any new Claude session can immediately understand the project state, architecture, known issues, and active design decisions without re-reading git history or debugging from scratch.

---

## What This Project Is

The Curator is a local Node.js web application that ingests text sources (PDF, MD, TXT) and automatically builds an interconnected knowledge wiki. The wiki is stored as plain markdown files, readable by Obsidian as a visual knowledge graph.

**Core loop:**
1. User drops in a source → LLM reads it → writes wiki pages (entities, concepts, summary)
2. Each subsequent ingest updates existing pages instead of duplicating them
3. Obsidian reads the same files → renders a graph where nodes are entities/concepts, edges are `[[wikilinks]]`

**Philosophy:** Compiled knowledge (persistent wiki), not retrieval (RAG). The wiki compounds with every ingest.

## Key Functions (files.js)

| Function | Purpose |
|---|---|
| `writePage(domain, relativePath, content)` | Normalise path → dedup passes A+B → cross-folder dedup (3b) → inject frontmatter → capture pre-write state → merge with existing → strip blanks → dedup bullets → strip folder-prefix links → normalize variant links (5c: entities + concepts + summaries, prefix-tolerant) → write → call injectSummaryBacklinks if summary → return `{canonPath, status, bytesBefore, bytesAfter, sectionsChanged, bulletsAdded}` (v2.5.0+; null on invalid input) |
| `compileConversation(domain, conversationId, onProgress, opts)` | Conversation compile: load conversation → refuse if fewer than `MIN_USER_MESSAGES` user turns (**1** since v3.0.1-beta.15, was 2) → compute deterministic summary slug `<title>-YYYY-MM-DD-<4hex>` → refuse if file already exists at slug (idempotency guard) → **3-step LLM ladder `full → concise → summary-only`** (v3.0.1-beta.27), escalating ONLY on `isOutputTokenLimit(err)` or a JSON parse failure; any other LLM error (503/429/auth/network) surfaces immediately → write all pages via the same writePage pipeline → syncSummaryEntities → programmatic mergeIntoIndex (no LLM-driven index regen) → appendLog → return `{ok, title, pagesWritten, changes, warnings}`. `opts.generateText` is a **test-only** seam (defaults to the real one) for driving the ladder offline. |
| `syncSummaryEntities(domain, summaryPath, writtenPaths)` | Post-ingest reconciliation: injects ALL written entity AND concept slugs into summary's "Entities Mentioned", then re-fires injectSummaryBacklinks with the complete list |
| `injectSummaryBacklinks(summarySlug, content, wikiDir)` | For each entity in "Entities Mentioned", injects `[[summaries/slug]]` into that entity's Related section; checks entities/ first, falls back to concepts/; creates the section if it doesn't exist |
| `deduplicateBulletSections(content)` | Safety net: removes duplicate bullets from all ACCUMULATE sections using dedupKey; runs after every write and after syncSummaryEntities |
| `mergeWikiPage(existing, incoming)` | Union merge: incoming is base, bullets from existing ACCUMULATE sections are injected (Key Facts, Related, Entities Mentioned, etc.). **Prose preservation (v3.0.1-beta.15):** any `## ` PROSE section present in `existing` but ENTIRELY ABSENT from `incoming` is preserved (case-insensitive match), so a thin Compile/Curate edit can't wipe an existing page's Definition / Summary / Why It Matters. If `incoming` includes the heading, incoming wins (no duplication). Exported for unit testing. |
| `injectBulletsIntoSection(content, sectionName, bullets)` | Dedup-aware bullet injection: compares by link target; creates the section if it doesn't exist (uses 'im' multiline regex for existence check) |
| `stripBlanksInBulletSections(content)` | Removes blank lines inside bullet sections (LLM artifact) |
| `normalizePath(relativePath)` | Redirects non-canonical folders → entities/ or concepts/ |
| `injectFrontmatter(content, path, today)` | Extracts inline Tags/Type/Source → builds YAML frontmatter block |

## Ingest Pipeline Flow

```
POST /api/ingest
  → ingestFile(domain, filePath, originalName)
      1. Save to raw/
      2. Extract text (pdf-parse or readFile), cap at 80k chars
      3. Load domain CLAUDE.md schema + current index.md
      4. Read existing entity/concept filenames → pass to LLM prompt
         (prevents LLM creating lumina.md when lumina-ai.md exists)
      5. Single-pass LLM call (< 15k chars input)
         OR multi-phase for large docs:
           Phase 1: outline → [{path, summary}]
           Phase 2: batched content (BATCH_SIZE=4 pages/call)
           Phase 3: index update
      5.5 Deduplicate result.pages — multi-phase can return the same path in
           multiple batches; keep last occurrence per path (Map dedup)
      6. writePage() for each page:
           a. normalizePath() — canonical folder enforcement
           a2. Underscore → hyphen slug normalisation — two_worlds_of_code.md → two-worlds-of-code.md
           b. Pass A: title-prefix strip — dr-tali-rezun.md → tali-rezun.md
           c. Pass B: hyphen-normalised dedup — talirezun.md → tali-rezun.md
           c2. Step 3b: cross-folder dedup — concepts/google.md → entities/google.md
               (prevents duplicate files when LLM misclassifies entity as concept)
           d. injectFrontmatter()
           e. mergeWikiPage() if file exists
           f. stripBlanksInBulletSections()
           g. deduplicateBulletSections() — safety net for merge edge cases
           h. Strip [[entities/...]] and [[concepts/...]] folder-prefix links
           i. Step 5c: normalize [[variant]] links using Pass A+B+C logic
              Pass A: [[dr-tali-rezun]] → [[tali-rezun]]
              Pass B: hyphen-normalised match against entities + concepts
              Pass C: prefix-tolerant match across all wiki files (entities, concepts, summaries)
              Catches [[energy-and-water-footprint-of-generative-ai]] →
              [[summaries/the-energy-and-water-footprint-of-generative-ai]]
           j. writeFile()
           k. If summary page: injectSummaryBacklinks() (entities/ + concepts/ fallback)
           l. Return canonPath — the actual path written to disk (may differ from input)
      7. syncSummaryEntities() ← THE KEY POST-WRITE STEP
           Uses canonicalPaths (returned by writePage), NOT original LLM paths.
           This ensures redirected slugs (dr-tali-rezun → tali-rezun) appear
           correctly in the summary. Injects ALL entity AND concept slugs into
           summary's "Entities Mentioned" → deduplicates → re-fires
           injectSummaryBacklinks() with the complete list →
           ALL entities/concepts get bidirectional backlinks
      8. writePage(index.md)
      9. appendLog()
```

## Known LLM Compliance Failures (and how they're handled)

The LLM produces structurally valid but consistently incomplete output. These patterns recur across every ingest regardless of model:

| Failure | Frequency | Code fix |
|---|---|---|
| "Entities Mentioned" lists 5–7 entities while 20–30 entity pages are written | Every ingest | `syncSummaryEntities()` in post-write step |
| Entity slug hyphen variation: `talirezun` vs `tali-rezun` | Common | Pass B dedup in `writePage()` (filename) + Pass B in `injectSummaryBacklinks()` |
| Title prefix ghost files: `dr-tali-rezun.md` | Occasional | Pass A strip + redirect in `writePage()` |
| `[[dr-tali-rezun]]` written as a link in page content | Occasional | Step 5c in `writePage()` normalizes all variant links at write time |
| Folder-prefix links: `[[concepts/rag]]` instead of `[[rag]]` | Common | `writePage()` step h strips `entities/` and `concepts/` prefixes |
| Multi-phase returns same page path in multiple batches | Occasional | `result.pages` deduped in `ingest.js` before the write loop |
| Duplicate bullets in sections (from multi-write edge cases) | Occasional | `deduplicateBulletSections()` safety net on every write |
| Entity has no Related section — backlinks silently dropped | New entities | `injectBulletsIntoSection()` now creates the section if it doesn't exist |
| Summary truncated — missing "Entities Mentioned" section entirely | Occasional (large docs) | `syncSummaryEntities()` adds the section if missing |
| Blank lines between bullets in a section | Common | `stripBlanksInBulletSections()` runs on every write |
| Underscore filename from PDF name: `two_worlds_of_code.md` | Occasional | Step 1a in `writePage()` converts `_` → `-` in the filename |
| Cross-folder duplicates: `concepts/google.md` when `entities/google.md` exists | Common | Step 3b cross-folder dedup redirects to existing file |
| Slug mismatch: `[[international-energy-agency]]` but file is `iea.md` | Occasional | Prompt strengthened + Step 5c Pass C prefix-tolerant matching |
| Missing article prefix in link: `[[energy-and-water...]]` vs `the-energy-and-water...` | Occasional | Step 5c Pass C strips `the-`/`a-`/`an-` prefixes for matching |
| Semantic near-duplicates in Key Facts ("25 years" vs "30 years") | Common | NOT fixed — requires LLM or manual curation |
| Concepts filed as entities (llm.md, cli.md, open-source.md) | Occasional | Caught by manual review; no automated fix |

## Post-Ingest Quality Checklist

Run these after any ingest where results look wrong:

```bash
# 1. Ghost author links (LLM uses "talirezun" or "dr-tali-rezun")
grep -rl "\[\[talirezun\]\]\|\[\[dr-tali-rezun\]\]" domains/articles/wiki/

# 2. Folder-prefix link violations
grep -rl "\[\[concepts/\|\[\[entities/" domains/articles/wiki/ | grep -v index.md

# 3. Duplicate bullets in any section
python3 -c "
import os, re
wiki = 'domains/articles/wiki'
for root, dirs, fnames in os.walk(wiki):
    for f in fnames:
        if not f.endswith('.md'): continue
        path = os.path.join(root, f)
        c = open(path).read()
        if len(re.findall(r'^## Related\s*$', c, re.M)) > 1:
            print('DUPLICATE RELATED:', path)
"

# 4. Duplicate Related sections (created by buggy section injection)
grep -rl "^## Related" domains/articles/wiki/ | xargs python3 -c "
import sys, re
for p in sys.argv[1:]:
    c = open(p).read()
    if len(re.findall(r'^## Related\s*\$', c, re.M)) > 1: print(p)
" 2>/dev/null

# 5. Run retroactive backlink repair if needed
node scripts/inject-summary-backlinks.js --domain=articles
# or all domains:
node scripts/inject-summary-backlinks.js
```

**Fix ghost links globally:**
```bash
# NOTE: every substitution needs its own -e. The first script cannot be bare
# when a second -e follows — BSD sed then reads "-e" as a FILENAME and exits 1
# having changed nothing (silent no-op; verified).
find domains/articles/wiki -name "*.md" -print0 | xargs -0 sed -i '' \
  -e 's/\[\[talirezun\]\]/[[tali-rezun]]/g' \
  -e 's/\[\[dr-tali-rezun\]\]/[[tali-rezun]]/g'
```

## Wiki File Conventions

**Three canonical folders only** — the code enforces this:
- `entities/` — specific people, tools, companies, frameworks, datasets
- `concepts/` — ideas, techniques, methodologies, principles
- `summaries/` — one page per ingested source document

**Link syntax** — always `[[page-name]]` without folder prefix, EXCEPT summaries which use `[[summaries/slug]]` because they live in a subfolder Obsidian needs for routing.

**YAML frontmatter** — every page gets it injected automatically by `injectFrontmatter()`. The LLM is instructed NOT to produce frontmatter. Type tags drive Obsidian graph coloring:
- `type/entity` → Blue nodes
- `type/concept` → Green nodes
- `type/summary` → Purple nodes

**Merge strategy** — bullet-accumulating sections (Key Facts, Related, Entities Mentioned, etc.) grow with every ingest. Prose sections (Summary, Definition) use the incoming LLM version (it had full document context).

```
.curator-config.json    — UI-managed config (API keys, domains path) — never committed
  geminiApiKey          — Google Gemini key (set via Settings tab / onboarding wizard)
  anthropicApiKey       — Anthropic Claude key (set via Settings tab)
  domainsPath           — custom path for domains/ folder (set via UI)

.env                    — developer fallback for API keys (never committed)
  GEMINI_API_KEY        — Google Gemini (default, recommended)
  ANTHROPIC_API_KEY     — Anthropic Claude (alternative)
  LLM_MODEL            — optional model override
  DOMAINS_PATH         — optional custom path for domains/ folder

.sync-config.json       — GitHub sync credentials (never committed)
```

**Key priority:** `.curator-config.json` (Settings UI) takes precedence over `.env` for API keys.
**LLM selection:** dispatch is on `getActiveProvider()` — **last-saved-wins** since v2.4.2. Saving a key in Settings makes that provider active, so with both keys stored the active one is whichever was saved most recently (and the Settings provider toggle flips it without re-pasting). `getProviderInfo()` in `llm.js` honours it, falling back to whichever provider still has a usable key if the active one's key is missing. Gemini-first-if-both applies only to **legacy configs with no `activeProvider` field**.
**Default models:** pinned in `DEFAULTS` in [src/brain/llm.js](src/brain/llm.js) — currently `gemini-2.5-flash-lite` / `claude-haiku-4-5` (Haiku is the low-cost tier chosen to match Flash Lite's cost profile; opt into Sonnet with `LLM_MODEL` in `.env`).

## Active Development Decisions

- **No vector DB / embeddings** — the decision stands, but **not** because the wiki fits in one context window; it stopped fitting long ago (the real `articles` wiki is ~4.4 MB against a 60 KB content budget). What replaced the "just send everything" assumption is **query-driven retrieval in `src/brain/chat.js`**: entity-pivot detection, keyword scoring, and a compact slug catalogue select the pages to load within `CONTENT_BUDGET_CHARS` (60 KB), `CATALOGUE_BUDGET_CHARS` (12 KB) and `MAX_PAGES_LOADED` (50). The reason to stay embedding-free is that the `[[wikilink]]` graph is already a hand-curated relevance signal, and markdown files stay human-readable and Obsidian-native — not that the corpus is small. (A blunt 90 KB `slice()` was the pre-beta.11 behaviour and was a genuine bug: on a mature domain the chat saw only `index.md` and `log.md`.)
- **No React/Vue** — seven-tab UI (Chat · Ingest · Wiki · Health · Domains · Sync · Settings) with vanilla JS. No build step.
- **JSON mode for ingest, text mode for chat** — ingest requires structured output; chat needs free prose.
- **Conversations gitignored from app repo but synced via knowledge repo** — personal to each user's machine, not committed to source control.
- **CLAUDE.md per domain** — each domain is a specialist, not a generalist. The schema shapes how the LLM categorises knowledge for that domain.
- **syncSummaryEntities is idempotent** — safe to run multiple times; injectBulletsIntoSection deduplicates by link target.
- **deduplicateBulletSections is always safe to run** — only removes bullets whose dedupKey already appeared earlier in the same section; never drops unique content.
- **API keys UI-first** — `.curator-config.json` (set via Settings tab / onboarding wizard) takes priority over `.env`. The `.env` file remains as a developer fallback.
- **install.sh auto-provisions** — detects and installs Node.js (via Homebrew or nodejs.org .pkg) and git (via Xcode CLI tools); no longer asks for API key during install (onboarding wizard handles it); auto-opens the app on completion.
- **No Stop button** — removed entirely because AppleScript's `on reopen` handler is broken on modern macOS and caused unrecoverable crashes. Closing the browser tab leaves the server running in the background (uses ~0 CPU). Clicking the Dock icon re-opens the browser if the server is running, or starts the server if it is not. To fully quit: right-click the Dock icon → Quit.
- **No /api/shutdown endpoint** — the server runs until the process is explicitly killed (Dock → Quit, or terminal Ctrl+C). No heartbeat or auto-shutdown.
- **Auto-update via Settings** — compares local `package.json` version with GitHub's `main` branch; runs `git fetch origin main` + `git reset --hard origin/main` + `npm install` + `bash scripts/build-app.sh` (rebuilds the .app); returns `{from, to}` short SHAs; frontend then calls `/api/restart` which spawns a new process and exits the old one. Browser auto-reloads. The hard-reset (instead of `git pull`) means the app directory is always forced to match `main` exactly — `package-lock.json` regenerated by local `npm install` runs no longer blocks the update.
- **Server auto-opens browser** — `exec('open http://localhost:3333')` runs on startup, unless `CURATOR_NO_OPEN=1` is set (used by the restart endpoint to prevent double browser tabs — the frontend reloads itself via polling).
- **Absolute node path in AppleScript** — `build-app.sh` and `install.sh` resolve the full path to `node` (via `which node`) at build time and embed it as `property nodeBin` in the AppleScript. This avoids the "node: No such file or directory" failure caused by AppleScript's `do shell script` running in a bare `/bin/sh` environment without the user's PATH. A `export PATH=...` with common node locations (`/usr/local/bin`, `/opt/homebrew/bin`) is also added as a fallback. If the user upgrades or moves Node.js, `bash scripts/build-app.sh` re-resolves the path.
- **Restart uses `process.execPath`** — the `/api/restart` endpoint uses the absolute path to the currently running Node binary (`process.execPath`) instead of bare `node`, ensuring the restarted server finds the same Node regardless of shell environment.
- **UI auto-refreshes after mutations** — after ingest, domain stats (page count, conversation count) update automatically; after sync down/both, domain dropdowns and stats also refresh; switching to the Domains or Wiki tab reloads their data. No manual browser reload needed.
- **Onboarding wizard** — **4**-step modal on first run (API keys → create domain → sync setup → connect Claude Desktop). **The trigger is CONFIG-ONLY:** `checkFirstRun()` ([app.js](src/public/app.js)) reads `hasGeminiKey || hasAnthropicKey` from `GET /api/config/api-keys`, which resolve through `getApiKeys()` — `.curator-config.json` **only, never `.env`**. So a developer running on `.env` keys alone gets the wizard on every load while the app can already make LLM calls, and because **step 1 has no Skip and the overlay has no Escape, no backdrop close and no X**, they are blocked until they paste a key into config. The only "don't show again" state is a key existing in config — which **any** Settings save sets, and a Settings **Disconnect** of the last key resurrects. Recorded as a known shipping defect; `/next`'s replacement is a non-blocking, dismissible panel (R7).
- **My Curator MCP (v2.3.0; read+write since v2.5.2)** — a local MCP server (`mcp/server.js`) that Claude Desktop spawns as a child process via stdio. Reads markdown directly from `getDomainsDir()`; does NOT require the Curator web server to be running. The authoritative tool list is the `tools` array in [`mcp/tools/index.js`](mcp/tools/index.js) — count it there rather than trusting a number in prose. As of v3.17.0 it holds **20** tools: **12 read** (list_domains, get_index, get_graph_overview, get_tags, search_wiki, search_cross_domain, get_node, get_connected_nodes, get_backlinks, get_summary, get_raw_source, get_working_state) and **8 grouped as write tools**, of which **5 actually mutate** (compile_to_wiki, fix_wiki_issue, dismiss_wiki_issue, undismiss_wiki_issue, save_working_state) and 3 are read-only inspections that happen to sit in that block (scan_wiki_health, scan_semantic_duplicates, get_health_dismissed). **Note the two valid splits, so they are never read as a contradiction:** this file counts by SOURCE GROUPING (12 read / 8 write-block), while user-facing copy — e.g. the `/next` MCP wizard — counts by CAPABILITY (**15 that read, 5 that write**), which is the more useful framing for someone deciding what to let Claude do. Same 20 tools, same 5 mutators. **Derive the mutator list from the `refuseIfReadonly` call sites across `mcp/tools/**`, never from this prose** — that call is what makes a tool a mutator, and v3.6.1 records a wrong count in a model-read doc actively changing Claude's behaviour. The graph tools are the reason MCP exists — they expose frontmatter, tags, [[wikilink]] edges (section-labeled), and bidirectional backlinks as structured data, so a frontier model can reason about topology, not just fetch pages. The generated `claude_desktop_config.json` entry uses absolute paths (`process.execPath` + `mcp/server.js` + `--domains-path <absolute>`); moving the domains folder makes it stale — the wizard detects staleness and shows a banner.
- **MCP wizard lives in Settings** — not a top-level tab. Section uses the sync-tab three-state pattern: **landing** (hero + what/privacy grid + "Set Up My Curator" CTA), **wizard** (3 numbered steps with progress pips: Copy snippet · Paste into config · Restart & verify), **connected** (status card + Self-test / View & Edit Config cards + runtime note). The wizard also joins the onboarding overlay as step 4 ("Connect to Claude Desktop", optional, skippable). Re-entering the Settings tab always refreshes the MCP status via `refreshMcpSection()` so stale UI can't persist after closing the wizard.
- **MCP response budget is in tokens, not bytes** — 1 MB of JSON ≈ 250 k tokens, which alone saturates Claude Opus's 200 k context window. `enforceSizeLimit()` in `mcp/tools/index.js` caps at **400 KB (~100 k tokens)** so a conversation can sustain multiple tool calls plus reasoning. The guard trims heavy arrays (edges → nodes → results → tags → backlinks → outgoing_from_start → backlinks_to_start) and appends `_truncated`. `get_graph_overview` default = compact summary (stats + top 20 hubs + orphan sample + top 10 tags, ~4 KB at any scale); `include_nodes: true` / `include_edges: true` are opt-in and size-guarded. `get_tags` default = top 50 tags with 50-page samples each. `get_connected_nodes` caps at `max_nodes: 60` (ranked by hop + degree), max depth 2, 120-char previews — enough to keep even hub-entity traversals under budget (e.g. `tali-rezun` at depth 2: 39 KB on the 2116-node articles domain).
- **MCP security** — defense in depth against LLM-driven path traversal. `storage/local.js` has a single `resolveInsideBase()` chokepoint that rejects absolute paths, `..` segments, and anything resolving outside the domains folder. Tools additionally validate their `domain`/`slug` args via `isValidDomain` / `isValidSlug` from `mcp/util.js` (strict alphanum+hyphen+underscore) for clean error messages. The `/api/mcp/reveal-config` endpoint uses `execFile` (not `exec`) so no shell interpretation. **The MCP is NOT read-only** (it was, up to v2.5.1; write tools landed in v2.5.2 — see the read+write-client bullet below). Five tools mutate user data — `compile_to_wiki`, `fix_wiki_issue`, `dismiss_wiki_issue`, `undismiss_wiki_issue`, `save_working_state` — and `fix_wiki_issue` can **delete** files (`crossFolderDupes` / `hyphenVariants` / `semanticDupe` all `rm()`). Each of those five, and only those five, calls `refuseIfReadonly()` before doing any work, so a Shared Brain `shared-*` mirror is refused. **Enumerate the call sites across `mcp/tools/**` rather than trusting this sentence** — it said "four ... and only those four" through the whole of v3.17.0, three bullets below its own correct count of five, and cited line numbers that had rotted by three. Any new mutating tool MUST add that call.
- **MCP graph cache** — `buildGraph()` caches per-domain with a 10-minute TTL and a file-count check for invalidation. An ingest that changes the file count forces a rebuild on the next tool call; otherwise graph re-use is safe for the life of one Claude Desktop conversation.
- **Model-lifecycle policy (v2.4.0)** — single chokepoint for all LLM calls is `generateText()` in `src/brain/llm.js`, which dispatches to whichever provider the user configured (Gemini or Anthropic). Default models are pinned in `DEFAULTS`; `FALLBACK_CHAINS` provides an ordered next-best list per provider. On model-not-found errors (and ONLY those — 429/503 still retry) the chain is walked in order; the successful model is recorded in a module-level `_activeFallback` and surfaced to the UI via `getFallbackStatus()`. When a provider retires a model: bump the `DEFAULTS` constant, optionally add the old primary to `FALLBACK_CHAINS`, push a release. Users on older versions keep working via the chain until they Check for Updates. Full user/developer guide: `docs/model-lifecycle.md`.
- **Self-test isolation** — `POST /api/mcp/self-test` spawns `mcp/server.js` locally, sends initialize + tools/list + list_domains over stdio, and reports round-trip results. If this passes but Claude Desktop still can't see the tool, the issue is in `claude_desktop_config.json`, not the bridge.
- **Semantic-duplicate scan is opt-in, cost-gated, and scale-capped (v2.4.5+)** — never runs as part of the regular Health scan. The flow is: estimate → confirm dialog → SSE-streamed real scan → per-pair Preview → Merge. Three hard caps in code: `SEMANTIC_DUPE_MAX_DOMAIN_PAGES = 20000` (refuses larger domains), user-configurable candidate-pair cap (default 500), user-configurable cost ceiling (default 50k tokens). **Batch merge is offered for HIGH-confidence pairs only** (`fixSemanticDuplicatesBatch`, `src/brain/health.js:1205`, added v3.0.1-beta.15): an explicit confirm step names how many pages will be deleted, merges run sequentially server-side (never in parallel — each merge rewrites links domain-wide), the route caps at 2,000 pairs, and — since every change lands in the git-tracked wiki — a user with Personal Sync configured can recover with a git client. **There is NO in-app revert: `src/routes/sync.js` has never exposed one**, and claiming otherwise on the panel that launches a page-DELETING operation was a false safety promise found at 14 sites and corrected in v3.9.1. **Medium- and low-confidence pairs are still one-at-a-time behind the mandatory Preview-diff gate** — they are the ones most likely to be genuinely distinct, and a wrong batch merge across thousands of pages is the most expensive mistake in The Curator.
- **Destructive-merge safety gate (v2.4.5+)** — Phase 3 is the first and only feature that DELETES files. The Merge button is disabled until the user opens the Preview-diff modal for that specific pair, which shows exactly which files will change, how many links will be rewritten, and what the merged content will look like. The frontend tracks previewed pairs per session; new sessions require re-preview.

It currently excludes machine-local and junk paths only: `*/raw/`, `*/.mcp-write-log.jsonl`, `*/.write-lock` (v3.0.15), `.DS_Store` (v3.0.16, deliberately un-prefixed so it matches at any depth), `.ingest-queue/` (v3.3.0, purely defensive), and `**/.obsidian/workspace.json`, `*.base`, `Untitled.md`, `Untitled 1.md` (v3.5.1 — the `**/` on the workspace rule is load-bearing per `gitignore(5)`). `conversations/*.json` is on none of those lists, so it IS tracked by the knowledge repo and travels with the wiki (documented in [sync.md](docs/sync.md): "so you can continue threads on any machine"). Community-reported as suspicious in v3.0.14 and deliberately left as-is. (CLAUDE.md's directory tree labels `conversations/` "gitignored" — that is true of the APP repo only.)
- **All user-data paths resolve through `src/brain/paths.js`; bundle detection is POSITIVE and fail-safe (v3.1.0+)** — an installed `.app` is read-only, so writing inside it breaks the code signature. `isBundleInstall()` requires an EXPLICIT signal (marker file or `<X>.app/Contents/` path shape); **everything else is repo mode — an unrecognised layout must ⇒ repo ⇒ data stays put.** Never invert this to "infer repo from markers, default to bundle": wrongly deciding "bundle" is catastrophic AND silent (empty wiki, data invisible), while wrongly deciding "repo" fails loudly on first write with nothing lost. Two earlier attempts were both wrong — `existsSync('.git')` alone (a ZIP download relocated everything) and data markers including `domains` (which `domains/.gitkeep` puts in EVERY shipped tree, making bundle mode unreachable). Any new user-data path MUST route through `paths.js` — there is exactly one root derivation in `src/`+`mcp/` and a source guard enforces per-call resolution (no top-level `const X = <getter>()`, which made an override silently import-order dependent). `scripts/build-app.sh` must NOT write the bundle marker while the `.app` remains an AppleScript wrapper around the checkout.
- **If a test spawns a server, isolate with `CURATOR_TEST_USER_DATA_DIR`, not `CURATOR_TEST_DOMAINS_DIR` (v3.1.0+)** — the latter isolates ONLY `domains/`, so a test server holds the developer's real `.sync-config.json` and GitHub PAT, and one stray Sync click pushes to their real repo. The new env is read before repo/bundle detection and re-read per call, so it crosses process boundaries; it isolates all four credential locations unconditionally, and `domains/` too UNLESS `DOMAINS_PATH`/`--domains-path` is set. (`scripts/test-sharedbrain-routes.js` still needs migrating.)
- **Give a clever test an independent dumb cross-check (v3.1.0+)** — `test-frontend-null-safety.js` was silently blind TWICE while reporting every assertion green: its lexer desynced on a nested template literal and on a regex containing backticks (seeing 78 of 90 declarations), and the rewrite then shipped a dead regex-vs-division heuristic that reopened the class. A parity tripwire could not catch it (two desyncs cancel). What works is a second, deliberately-dumb measurement compared for exact SET equality — it fires even on shapes the sophisticated path still misses. Same lesson as v3.0.15's CSS-token baseline and v3.0.17's source-regex assertion: a passing test that measures the wrong thing is worse than no test.
- **Assert behaviour, not the presence of a line of source (v3.0.17+)** — `test-ingest-prompt-slimming.js` asserted the CALL SITE of the Phase 1 usage report with a source regex and labelled it "the pages-vs-tokens datapoint sizing needs". The value it reported was ALWAYS wrong on the retry path (a dead `if (outline)` conditional inside `if (!outline)`), and the source assertion gave positive assurance the whole time. A test that proves a line exists proves nothing about what it does. `ingestMultiPhase` now takes a trailing defaulted `llm` param — a TEST-ONLY seam (same pattern and rationale as `compile.js`'s `opts.generateText`, null in production) that drives the real Phase 1 retry ladder and Phase 2 fallback ladder against a fake LLM, offline and free. Building that seam is what surfaced the lenient-`parseJSON` bug below; prefer it over source regexes for anything orchestration-shaped.
- **Apply a fix to the path that runs FIRST, not just the path you were looking at (v3.0.17+)** — v3.0.16's `extractPageArray` closed a silent-drop hole on the single-page FALLBACK while the batch path, which runs first for every batch of every multi-phase ingest, kept the original bug: `{"pages": []}` is truthy, so a whole batch's pages vanished with no stub, no warning, and a green result panel; `{"pages": {}}` threw `TypeError` and killed the ingest. When fixing a response-shape bug, enumerate EVERY call site that consumes that shape before declaring it closed.
- **`parseJSON` is lenient and its output must be validated, not merely truth-tested (v3.0.17+)** — it falls back to jsonrepair, which turns the bare text `not json at all` into the truthy STRING `"not json at all"`. An `if (!parsed)` check accepted that as a successful outline, skipped the retry, and `validateOutline` degraded it to a summary-only plan — an 80,000-char source could produce a ONE-PAGE wiki. Any `parseJSON` result that is supposed to carry a page list must go through `usablePageArray`/`extractPageArray`, never a truthiness check.
- **Repeated warnings aggregate at emission, and two classes deliberately do not (v3.0.17+)** — `aggregateWarnings()` collapses same-class entries at ONE chokepoint before the log entry is built, so `log.md`, the SSE payload and the result panel cannot disagree. Threshold is 3 (1–2 occurrences keep the specific path, which is the useful thing; 3 is the same "pattern, not incident" line the trunk-page detector uses), examples capped at 3 with "…and N more". A real run went 75 → 11. **Semantic near-duplicates and trunk-page injections are excluded on purpose** — each names a specific pair or cluster the user must decide about; collapsing them trades signal for tidiness. When adding a warning that can fire per-page or per-batch, add it to the aggregator; when adding one that names a decision, do not.
- **The batch prompt's stable prefix is load-bearing — never let it vary per call (v3.0.16+)** — `buildBatchPromptParts` returns `{prefix, suffix}` and the ENTIRE cost win of v3.0.16 depends on `prefix` being byte-identical across every batch of one ingest. Anything per-call in it (a timestamp, a counter, Set/Map iteration order, or moving the page list back out of `suffix`) silently turns every cache READ into a cache WRITE at 1.25×, making ingest **more expensive** — with no error, no warning, and no offline test able to see it. The only proof is a live multi-batch run showing non-zero `cachedReadTokens` (Anthropic) — verified at write=41,822 / read=250,932 = 56.6% saving. Anthropic caching is gated BOTH by a size floor (`ANTHROPIC_CACHE_MIN_PREFIX_CHARS`, because Haiku 4.5 silently declines to cache under ~4,096 tokens) and by `totalBatches >= 2` at the caller (break-even is two calls); single-pass must never get a breakpoint.
- **The broken-wikilink rate is not a valid single-run gate (v3.0.16+)** — measured on UNMODIFIED v3.0.15 against an md5-frozen source and a fixed articles-scale domain, it ranges **Gemini 0.0–3.8%** and **Anthropic 2.4–6.1%**. That noise is wider than any effect a prompt change is likely to have, so an A/B at n=1–3 will confidently report an improvement or a regression that does not exist (this happened twice in the v3.0.16 work, in both directions). Use paired runs with several replicates per arm, compare against the paired baseline rather than the fixed 1–5% band, and — where the question allows — prefer **byte-identity of the generated prompt** over a statistical argument: it is deterministic and settles in seconds what 14 live ingests could not.
- **Ingest warnings are the contract for anything the pipeline silently changed (v3.0.16+)** — `writePage`'s `opts.onWarn` and `reconcileGeneratedPages` exist because two failure modes were losing user-paid-for content with only a `console.warn`: a page path missing `.md` was discarded outright, and a Phase 2 response returning a non-canonical `summaries/` path created a SECOND summary, permanently breaking that source's re-ingest idempotency. Rule: if the pipeline drops, redirects, renames, or flattens something the model produced, it MUST push a user-visible entry into `warnings[]` — a stderr line is not a user surface. `validateOutline`'s guarantees bind the OUTLINE only; anything Phase 2 returns must be re-validated against the paths that batch actually requested.
- **The Gemini fallback chain must escalate FORWARD in time, and every rung must be priced (v3.0.15+)** — `FALLBACK_CHAINS.gemini` exists to keep users working when the pinned default is retired, so it must list *newer* models, never older ones. The pre-v3.0.15 chain pointed at `gemini-1.5-flash*`, both of which were already **404** — the safety net had one working rung. When adding a rung: probe it live with the app's real call shape (JSON mode + `maxOutputTokens: 65536`), add its price to `MODEL_PRICES_USD_PER_MTOK` (an offline invariant in `test-chat-model.js` fails `npm test` otherwise), and never describe a rung as "same cost tier" without checking — a family-name heuristic is structurally wrong because the family word is stable across generations while the price is not (`2.5-flash-lite` → `3.1-flash-lite` is 2.5× in / 3.75× out; `haiku-4-5` → `3-5-haiku` is genuinely *cheaper*). `DEFAULTS.gemini` stays on the cheapest working model; the chain is insurance, not a migration.
- **The boot guard lives in `index.html`, not `app.js` (v3.0.15+)** — a handler inside `app.js` cannot catch `app.js` failing to evaluate, which is the exact case (~79 top-level `getElementById` consts; one missing element blanks the page for every user via the auto-updater). Only the `window.__curatorBooted` sentinel, set on `app.js`'s last line and checked at `DOMContentLoaded`, is authoritative — do NOT add filename-based resource-error heuristics, because the SPA fallback serves `index.html` with a **200** for any missing path, so a missing script throws a `SyntaxError` rather than a resource error. A missing `markdown.js` is NOT fatal (`app.js` has a designed escaped-text fallback) and must never trigger the panel.
- **CSS custom properties fail silently — `npm test` guards them (v3.0.15+)** — an undefined `var(--x)` makes the declaration invalid at computed-value time (inherited properties fall back to `inherit`, so it often looks *almost* right). [test-css-tokens.js](scripts/test-css-tokens.js) fails on any new undefined reference and carries named regression guards for `--font-mono` and `--text-1`. Three fallback-carrying names (`--text-primary`, `--text-secondary`, `--surface-1`) are deliberately baselined — re-pointing them at real tokens would change rendered colours, which belongs with the design-system work. Never add a variable to the baseline to make the suite pass.
- **`push()`, `pull()` and `setup()` must all guard their commit (v3.0.15+)** — any `git commit` that can be reached with a clean index must be wrapped in `if (!err.message.includes('nothing to commit')) throw err`. `friendlyError` maps that message to `null`, so an unguarded throw surfaces as an **empty** error the user cannot act on or recover from. `untrackStaleWriteLocks()` made this reachable in `push()` by staging a deletion that `git add -A` then cancels.
- **A prior version is content or `null` — never `''` (v3.1.1+).** `loadPriorContent`'s pathspec is **work-tree-relative** (`<domain>/wiki/<path>`) because Personal Sync passes `--work-tree=getDomainsDir()`; a `domains/` prefix matches 0 of ~5,200 tracked files and silently disables every delta. Beyond that, `isNew` is a `=== null` identity check while `buildDeltaPrompt` branches on **truthiness**, so an empty-string prior makes the prompt self-contradictory ("IS NEW PAGE: false" + the new-page block) and the model can route real content into `stable_facts`, **which nothing reads** — permanent loss. 0-byte pages are ordinary input (Obsidian creates them on "new note" and the vault root IS `domains/<d>/wiki/`), so `if (!content) return null` is load-bearing, not defensive. Whitespace-only is deliberately NOT caught — it is truthy, so both consumers already agree. Do not over-credit `--literal-pathspecs`: it has been over-claimed twice and now guards no observable output difference.
- **Pages that never reached the collective must never be diffed (v3.1.1+).** A page in `pending_retry`/`permanent_skip` failed its last push, so none of its body was contributed; diffing it against the pre-failure git version drops everything that was never sent. Freeze the membership set off `connection` BEFORE the un-skip loop mutates the working copies. Redundant full contributions are absorbed by exact-string dedup; a gap is unrecoverable — always prefer the redundancy.
- **`getProviderInfo` FALLS THROUGH — never infer the provider from the label (v3.1.1+).** With no key for the requested provider it silently returns whichever provider still has one. Any test that redirects user-data paths also redirects `.curator-config.json` (where the Gemini key lives; it is not in `.env`), so a "per-provider" suite can run one model twice and pass. Seed the isolated config AND assert the resolved provider. Byte-identical output from two different models is the tell.
- **`npm test` must never touch a real credential file (v3.1.1+).** Suites needing a different domains dir use `__setDomainsDirOverride()` (in-process, domains-only) or `CURATOR_TEST_USER_DATA_DIR` (anything spawning a server) — never by deleting the real config so `DOMAINS_PATH` can win. Fingerprint guards compare **sha256 + size + existence only**: `mtime` makes them fail when the maintainer's live app rewrites config during an ordinary Settings action, producing a false "isolation is broken" — the misattribution shape that cost two investigations in v3.0.16.
- **Batch ingest queue invariants (v3.3.0+)** — the queue directory resolves through `getIngestQueueDir()` in `paths.js` and **must never live inside `getDomainsDir()`** (that is Personal Sync's git work-tree; staged sources would be committed and pushed). Execution is **strictly sequential and process-wide**: the worker/create claims are taken **synchronously**, with no `await` between check and set, and a second independent in-flight counter asserts "at most one `ingestFile` ever" around the call itself — do not "fix" a concurrency report by adding another check after an `await`, that narrows the window rather than closing it. **Duplicates are decided once, at create time, and the worker performs no duplicate check** — `ingestFile` writes `raw/<name>` first, so a runtime check would mark a crash-resumed item `skipped` and silently drop it. A **transient** provider error (structured `err.curatorTransient` tag from `llm.js`, never a bare `/\b429\b/` — that also matches ingest's own `"yielded only 429 characters"`) pauses the whole batch; anything else fails one item; and a **consecutive-failure circuit breaker** bounds the harm regardless of classification. A recovered job comes back **`paused`, never running** — nothing may auto-start spend. `toWire()` is an explicit **allow-list** with length caps and path scrubbing; never reintroduce a `...rest` spread. A `budgetUsd` that cannot be priced is **refused (400)**, never silently accepted — and the cap guarantees spend is *tracked and bounded*, not that it is never exceeded. The estimate quotes a multiple **computed for the batch in front of it**; the fresh-vs-mature ratio is size-dependent (**39.4× at 2 KB → 2.1× at 80 KB**, with a step at ~15,000 chars where a source crosses to multi-phase) so **never hard-code a single multiplier** — a test asserts the multiple must move with document size.
- **Memory-layer (working state) invariants (v3.17.0+, hardened v3.17.1–.2)** — **state SUPERSEDES; knowledge ACCUMULATES**, and that is why there are two stores rather than one. The wiki's merge unions bullets, so a blocker resolved on Tuesday would be resurrected by Wednesday's write; a union merge cannot express *no longer true*. **`state/` therefore never goes through `writePage`** — and could not, even if wanted: `normalizePath` redirects every non-canonical folder and FLATTENS to the basename, so `sessions/projA/main/state.md` and `sessions/projB/feature-x/state.md` BOTH land on `entities/state.md`, the second silently overwriting the first. `(project, scope)` is inexpressible through that path. **The `<machine>` segment is load-bearing and must not be collapsed or 'simplified':** Personal Sync resolves with `git pull --no-rebase -X theirs`, which on a conflicting hunk silently discards the local side and reports success, so per-machine paths mean no hunk ever conflicts. It is `<hostname-slug>-<install-id>`, never a bare hostname — two clones sharing a default macOS name destroyed a handoff and its journal. **That argument covers tiers 2 and 3 ONLY:** `state/project.md` has no machine segment, so two machines editing the standing brief DO produce the conflicting hunk — the one place the guarantee does not hold, and `docs/sync.md` carves it out. **Single writer:** agents write over MCP; the app is READ-ONLY over state, deliberately — a browser write path would make the app a SECOND writer and break the property the whole sync-safety argument rests on, and would stamp a human edit with the last agent's provenance. **The standing brief is human-authored** and there is deliberately no brief-writing MCP tool. **Capture is skill-instructed and ADVISORY** (`claude-skills/curator-continuity/`): nothing forces a save, and a missed one yields the PREVIOUS state, never a corrupted one — the fail-safe direction, and the reason no enforcement was added. Saving OVERWRITES and is therefore idempotent, so the instruction is **save early and often**, and **every save must be COMPLETE, not a delta**, or the third save silently drops the firm decisions recorded in the first. **An over-budget save is TRIMMED and disclosed in `notes`, never refused** — an agent near its context limit whose handoff is rejected loses it entirely. **Counts are taken BEFORE the index slice:** `distinctScopeCount` counts distinct scopes over the UNCAPPED pair list, because deriving it from the capped array reports a CAP as a measurement. **`scopeCount` is a LEGACY name meaning two different quantities** — distinct scopes on `GET /api/memory`, the (scope, machine) pair total on `GET /api/memory/:project` — both pinned by different suites, so neither was redefined; read `distinctScopeCount` and `savedCopies`, which mean one thing each everywhere. **`resolveInsideState` is the sole path chokepoint.** Sanitisation runs on READ as well as write, and defang **never deletes** — a legitimate handoff routinely carries URLs and commands. **The dominant defect class here is a consumer silently dropping a field the store honestly computed** (`unlistedEntries`/`unlistedReason`, `requestedMachine`, `machineIsThisHost`, `installIdAvailable`): guarded BEHAVIOURALLY by `scripts/test-working-state-disclosure.js`, never by a name scan — `res.json({ ...state })` and `out.current = state.current` forward fields wholesale, so a text search reports drops that are not real and misses real ones.

## Known benign GitHub behaviours

- **"Sorry, we had to truncate this directory to 1000 files"** on GitHub's web UI when browsing `domains/articles/wiki/concepts/` (or similarly busy folders) is a **GitHub rendering limit, not a sync issue**. Git itself handles millions of files per directory; the truncation only affects the file-listing view on `github.com`. Clone the repo locally, or use `git log` / `git ls-files`, and you see everything. Sync push/pull transfers all files correctly regardless of this UI limit.
